# `.gitignore`

**Location:** `DM_Project/.gitignore` (project root)
**Roadmap step:** File 01 (Stage 0, setup)

## Purpose

Tells Git which files and folders it must never track. In this project that means the dataset, the generated data, the trained models, the reports and the logs. They are large, regenerable and in some cases hold the full dataset, which the master prompt says must not be committed by default.

## What it ignores

| Group | Rules | Why |
|---|---|---|
| Data and generated outputs | `/data/`, `/dataset/`, `/artifacts/`, `/reports/`, `/logs/` | The dataset is large. Everything in these folders can be regenerated by running the scripts |
| Model files | `*.joblib`, `*.pkl` | Trained models can be very large and are rebuilt by `scripts/05_train.py` |
| Python | `__pycache__/`, `*.py[cod]`, `*.egg-info/`, `build/`, `dist/`, `.pytest_cache/`, `.coverage`, `htmlcov/` | Build and cache files created automatically |
| Virtual environments | `.venv/`, `venv/`, `env/` | The environment is rebuilt from `requirements.txt`, never committed |
| Secrets | `.env`, `.streamlit/secrets.toml` | Prevents accidentally publishing credentials, should any ever be used |
| Editors and notebooks | `.vscode/`, `.idea/`, `.ipynb_checkpoints/` | Personal editor settings |
| Operating system | `.DS_Store`, `Thumbs.db`, `desktop.ini` | Folder metadata files |

## What it deliberately does not ignore

Source code, `config/`, `scripts/`, `app/`, `tests/`, `docs/`, `README.md`, `requirements.txt` and `pyproject.toml`. In particular, the source package `src/nids/data/` is tracked even though a top-level `/data/` folder is ignored (see the first common error).

## Inputs and outputs

- **Inputs:** none. It is a plain text file.
- **Output:** none. It only changes how Git reports and stages files.

## Dependencies

None. It is created first, before the first data folders exist.

## How to create and verify it

Create `.gitignore` in `DM_Project/` (in VS Code: right-click the root folder, "New File", name it `.gitignore`). Then, from the project root in PowerShell:

```powershell
git --version                 # confirms Git is installed
git init                      # only if the folder is not a Git repository yet

# Paths that must be ignored (each command prints the matching rule):
git check-ignore -v data/raw/Monday.csv
git check-ignore -v artifacts/models/trained/knn.joblib
git check-ignore -v .venv/Scripts/python.exe

# Paths that must NOT be ignored (each command prints nothing):
git check-ignore -v src/nids/data/loader.py
git check-ignore -v config/settings.py
```

`git check-ignore` works even if the files do not exist yet.

**Expected result:** the first three commands print a line such as `.gitignore:8:/data/    data/raw/Monday.csv`. The last two print nothing.

## Common errors

| Problem | Cause | Fix |
|---|---|---|
| Source files under `src/nids/data/` do not show up in `git status` | The pattern was written as `data/` without the leading slash. Unanchored, it matches **every** folder named `data`, including our source package | Keep the leading slash: `/data/`. It applies only to the folder at the project root |
| The same problem for `reports/` or `logs/` | Same cause | Keep the anchored forms `/reports/`, `/logs/`, `/artifacts/` |
| Windows saves the file as `.gitignore.txt` | Created with "New text document" in Explorer | Create it in VS Code, or rename it to remove the `.txt` (enable "File name extensions" in Explorer) |
| A file that was already committed is still tracked after being added to `.gitignore` | `.gitignore` only affects untracked files | Run `git rm -r --cached <path>` once, then commit |
| `git` is not recognised | Git is not installed or not on the PATH | Install Git for Windows, or skip this verification (the file is still correct as plain text) |

## Decisions and limitations

- **Anchored folder rules.** We tested that `/data/` ignores `data/raw/...` but leaves `src/nids/data/loader.py` tracked, and that the unanchored `data/` would wrongly ignore the source package.
- **`*.joblib` and `*.pkl` are ignored everywhere,** not only in `artifacts/`, so a model saved to an unexpected place is still not committed.
- **`.vscode/` is ignored.** If you later want to share editor settings with others, remove that line.
- **`docs/` is tracked,** since the per-file documentation is part of the deliverable.
